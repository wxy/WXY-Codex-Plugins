# Verification and replay

## Automated end-to-end flow

Prerequisites: macOS or Linux, Python 3.9+, local writable temporary directory, hardlink and sparse-file support. No network, model, account credentials or third-party runtime packages are needed.

From repository root:

```sh
python3 tests/e2e.py --output artifacts/e2e
```

The runner allocates a unique `codex-footprint-e2e-*` directory under the system temporary directory. Inputs are generated by the checked-in runner: an existing 256 KiB historical cache, a 192 KiB build output created through an actual external Python process, further 64 KiB growth, twelve tiny files, a hardlink pair, a sparse file, an outside-directory symlink and a deliberately missing root. Lower thresholds make signals observable without allocating gigabytes. Hook commands are loaded from `hooks/hooks.json` and executed with `PLUGIN_ROOT`, `PLUGIN_DATA`, explicit test configuration and documented Codex event payloads. A directory containing spaces verifies quoting.

Outputs on every completed run, including failures:

- `report.json`: cases, results, duration, full evidence, environment, prerequisites, command and inputs.
- `report.md`: concise human-readable acceptance report.
- `transcript.json`: CLI/MCP/hook messages and diagnostics for replay/debugging.

The fixtures are removed on exit. Reports retain the data and inputs needed to regenerate them. Paths in generated reports refer to the now-disposed isolated fixture, not the user's projects.

Coverage includes baseline/history, real process growth, sustained/many-file signals, hardlink/sparse/symlink boundaries, five MCP tools and handshake, invalid inputs, non-destructive plans, budget exhaustion, overlap rejection, missing roots, concurrent hook processes, privacy minimization, fail-open malformed input, unconfigured inactive mode, retention, local archive relocation and reproducible packaging. These are black-box tests; there are no implementation-mirroring unit tests.

The skill entrypoint can also be validated with the Codex skill-creator `quick_validate.py`. That checks metadata/structure; it is not a substitute for behavior verification.

## Isolated host package smoke test

```sh
python3 tests/host_package_smoke.py --output artifacts/host-package
```

Requires a compatible Codex CLI. The test creates a disposable Codex child-process profile in the system temporary directory, adds this local marketplace and installs the plugin there, then deletes the entire temporary profile. It never changes the user's personal Codex configuration, trusts hooks or calls a model. The report records CLI version, commands, inputs, install receipt and outputs. Passing proves host package recognition/installation, not real lifecycle delivery.

## Real Codex Desktop acceptance (pending)

Use a disposable workspace and a deliberately small explicit root. Configure a stable state path shared by both transports. Install from the local marketplace and trust the reviewed hooks in the host; do not bypass hook trust. Record Codex version and configuration.

1. Open a fresh chat and verify `footprint_status` sees the intended roots/state directory.
2. Request a small build/artifact creation through a real shell tool. Verify SessionStart/UserPromptSubmit and matched PreToolUse/PostToolUse records exist.
3. Query `footprint_report` using the real session/turn IDs. Compare observed allocated growth against the known artifact; require complete endpoints and matching snapshot IDs.
4. Query explain and cleanup-plan. Verify no artifact changes or deletions occurred, and attribution remains temporal correlation.
5. Run two simultaneous tasks and an interrupted task. Check that incomplete windows remain unknown and overlapping correlations are not added into a false unique total.
6. Disable the plugin, then verify no new automatic observations arrive. Re-enable/trust again as required and verify the same stable history path.

Archive the host event evidence, MCP results, generated artifact metadata, exact commands, inputs, expected/actual outcomes and host prerequisites. Until this is done, report "automated transport E2E passed; real-host acceptance pending", not "automatic Codex monitoring accepted".

## Local package verification

```sh
python3 scripts/codex_footprint.py package --output dist
```

Expected: complete local ZIP plus SHA-256 receipt. A second build from identical source produces the same archive hash. The E2E runner extracts and executes the shipped CLI and confirms hooks, MCP wiring and local marketplace metadata are retained. No official publication is part of current acceptance.
