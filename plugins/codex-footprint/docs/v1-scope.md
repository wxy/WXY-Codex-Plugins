# V1 scope and acceptance boundary

## Implemented

- Independent repository and Codex compatibility manifest; no changes to another project or global Codex settings.
- Seven lifecycle events, fail-open hook adapter, opt-in explicit roots and bounded metadata observation.
- SQLite history, same-scope session/turn baselines and tool-call windows.
- Large occupancy/growth, average growth rate, many files and sustained growth signals.
- Historical heavy hitters from first retained observation and bounded top-file records.
- Five local MCP tools, CLI, non-executing cleanup review plans and local ZIP packaging.
- Complete reproducible local packaging and an archived record of the earlier marketplace assessment.
- Black-box E2E fixtures using real files, external writer process, packaged hooks and MCP protocol messages, with replayable reports.

## Not yet accepted or implemented

Real Codex Desktop hook trust/delivery and MCP configuration in the user's installed environment remain a separate acceptance task. The automated tests drive the packaged hook commands with documented input and use real MCP stdio, but do not prove that a live model/host invokes every event.

Verified external-process write attribution, a continuously running observer, in-tool sampling, transient peaks, daemon/background descendants, cross-session unique ownership, filesystem event subscriptions, daily rollups, inactive-artifact inference, Docker internals, Windows support, UI and reminders remain future work. V1 is a coherent executable skeleton, not a comprehensive system-wide profiler.

The user chose personal local use. Official-marketplace publication is outside the current scope; a skills-only replacement is not part of the product. No remote server, telemetry, network upload, delete/execute tool, global installer, release tag, GitHub remote or public submission is created by V1.

## Next bounded stage

1. Validate the complete local flow in a disposable real Codex chat: install, trust hooks, baseline, build, query MCP and compare evidence. Preserve logs and host/version details.
2. Measure hook overhead on a real development root and add periodic/in-tool observation only where event snapshots miss meaningful growth. Preserve attribution limits.
3. Add history rollups or a panel/reminders after useful observations are proven in personal use.
